TL;DR — Write context down once. Point to it instead of re-explaining. Every session you retype the same three paragraphs is a session you haven't written a CLAUDE.md yet.

D. Document Over Teach. References Over Recitations.

Every new agent session starts blank. No memory of last week. No knowledge of your naming conventions, deployment setup, or which module is off-limits. So people explain. Again. And again.

This is wasted work. The AI doesn't need to be taught — it needs to be pointed at.

"The palest ink is better than the best memory." — Chinese proverb

Document over teach

When you're tempted to explain something in a prompt, ask whether it belongs in a file instead.

  • you can keep multiple files in directory like AGENTS/ and reference them from a central .md like AGENTS.md so only relevant parts are read — see Belief B on keeping prompts short)
  • A complex one-off task → myprompts/task.md

Once it's written, you stop explaining. You reference. See @AGENTS.md for conventions is five words. The alternative is rewriting the same context paragraph every session for the rest of the project's life.

Reference over recitation

Don't paste content into your prompt. Point at it.

Recitation:

The project uses TypeScript strict mode. We follow Airbnb style. Errors 
should be typed. We use Zod for validation. The src/ directory contains...

Reference:

follow @AGENTS.md conventions and implement @tasks/feature.md

Keep AGENTS.md modular, reference and separate files for conventions, gotchas, workflow. The model reads only what's relevant when you reference a file directly. Dumping everything into one block risks diluting

In practice

  • /learn command is specifically made to take things the model discovered or you explained, and persist it as documentation for later agents.
  • a lot of commands produce reports where you later can reference content. It can still be efficient to copy paste subsections from reports into the context.
    • it is the same as retyping the same instructions to an amnesiac LLM that does not pay off.
  • Also never argue with an LLM. If you know it is wrong. Just ask it to dump any useful correct context. start a new session, reference files make it easy getting the new agent up to speed.

Counter-arguments

"Documentation gets outdated faster than prompts." Only if you maintain it separately from the code. Keep CLAUDE.md in the repo and update it when the code changes. A stale doc is a process problem, not an argument against the approach.

"Sometimes a quick explanation is faster." For a genuine one-off, yes. The question is: will I explain this again? Most project context has the answer "yes." Document it now.

"The model doesn't always follow referenced files faithfully." A real limitation — write clear, specific docs and verify. It's still more reliable than hoping you phrase the inline explanation correctly every time.
