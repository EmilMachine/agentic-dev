TL;DR - Referer til filer med @filnavn. Send prompts som filer: follow @filnavn eller uden at åbne CLI'en claude < tasks/task.md. Skriv output til filer: analyze @src/ and write report to myreports/out.md. Slå auto-redigering til og fra med shift+tab.

Filer som input og output

De fleste bruger Claude Code som de bruger ChatGPT: skriv et spørgsmål, læs svaret. Det virker, men det misser pointen. Dette indlæg handler om de tre mønstre, der faktisk ændrer måden du arbejder på.

Forudsætter at du har Claude Code installeret. Hvis ikke, start med Indlæg 0.

Analogi - Filer

  • Chat er som en post-it lap - hurtig at skrive, nem at miste. Luk fanen og den er væk.
  • Filer er som et arkivskab: du lægger noget ind, og du kan finde det igen senere.
  • Når du arbejder via filer, er dine prompts, kontekst og output der stadig, når du vender tilbage. Intet begravet i et chatvindue.

Mønster 1: Referer direkte til filer

I stedet for at kopiere kode ind i chatten, peg på den:

add error handling to @src/api/fetch.ts

@filnavn-syntaksen trækker filen ind i konteksten. Claude læser den, redigerer den og skriver resultatet tilbage. Du indsætter ikke, du kopierer ikke ud.

(Claude klarer det som regel også uden @)

Mønster 2: Prompt som en fil

For alt mere end én sætning, skriv din prompt i en .md-fil og send den:

see @tasks/add-auth.md and implement it.

Dette gør prompts versionsstyrede, gentagelige og delbare. En fil du kan committe er bedre end en chatbesked du mister.

Mønster 3: Output som en fil

Bed Claude om at skrive sit output et bestemt sted:

analyze the performance bottlenecks in @src/ and write a report to myreports/perf-notes.md

Nu er outputtet i dit repo, ikke begravet i et chatvindue.

Sæt det hele sammen

En rigtig session ser sådan ud (forudsat du har mappen myprompts/task1):

  1. Skriv en opgavebeskrivelse i myprompts/task1/0_context.md
  2. Kør claude og referer til den: implement @myprompts/task1/0_context.md write a changelog to myprompts/task1/1_changelog.md
  3. Gennemgå diff'et, commit det du vil have

Hvis det ikke er tilladt, beder den om godkendelse for hver enkelt redigering. Du kan aktivere auto-redigering enten via "tillad ændringer for denne session" eller ved at trykke shift+tab. Det vises som "⏵⏵ accept edits on" - shift+tab igen for at deaktivere.

Du har altid git-versionsstyring og git diff i ryggen - men i praksis er det sjældent nødvendigt.

Jeg plejer at have en myprompts/-mappe med en .gitignore *-fil, så de rodede noter ikke committes. Vigtige ting destilleres til rigtige artefakter som README.md.
